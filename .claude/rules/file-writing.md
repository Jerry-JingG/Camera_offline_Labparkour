# 文件写入规则 (File Writing Rules)

## 分批写入长文件

**关键要求**：当需要写入超过 50 行的文件时，必须分多次写入，避免一次性写入过多内容。

### 写入策略

#### 1. 新文件创建（超过 50 行）

```markdown
步骤：
1. 使用 Write 工具写入前 50 行内容
2. 使用 Edit 工具追加后续内容（每次不超过 50 行）
3. 重复步骤 2 直到完成所有内容
```

#### 2. 文件编辑

```markdown
- 小改动（< 50 行）：直接使用 Edit 工具
- 大改动（> 50 行）：分多次使用 Edit 工具
- 完全重写：先 Read 确认，再分批 Edit
```

### 示例

#### 错误做法 ❌

```python
# 一次性写入 200 行的文件
Write(file_path="long_file.py", content="... 200 lines ...")
```

#### 正确做法 ✅

```python
# 第一步：写入前 50 行
Write(file_path="long_file.py", content="... first 50 lines ...")

# 第二步：追加第 51-100 行
Edit(
    file_path="long_file.py",
    old_string="... end of first 50 lines ...",
    new_string="... end of first 50 lines ...\n... next 50 lines ..."
)

# 第三步：追加第 101-150 行
Edit(
    file_path="long_file.py",
    old_string="... end of first 100 lines ...",
    new_string="... end of first 100 lines ...\n... next 50 lines ..."
)

# 继续直到完成...
```

### 行数阈值

| 行数范围 | 操作方式 |
|---------|---------|
| 1-50 行 | 一次性写入 |
| 51-100 行 | 分 2 次写入 |
| 101-200 行 | 分 3-4 次写入 |
| 200+ 行 | 分 5+ 次写入 |

### 重要提醒

1. **预估行数**：在写入前评估总行数
2. **逻辑分块**：按照代码逻辑或文档章节分块
3. **验证完整性**：写入完成后使用 Read 工具验证
4. **避免截断**：不要在代码块或段落中间分割

### 分块建议

优先在以下位置分块：
- 函数或类定义之间
- 文档的章节之间
- 配置文件的不同部分之间
- 导入语句和主代码之间

### 错误处理

如果一次性写入失败：
1. 检查是否超过行数限制
2. 将内容分成更小的块
3. 使用 Edit 工具逐步追加
4. 验证每次写入的结果
